## 1. Core Mission & Design Principles

Atlas Steward is an autonomous community operations agent designed to maintain essential community infrastructure (specifically municipal water points, pumps, tanks, and treatment units) according to a durable human objective:

> *"Keep all community water points operational this week. Handle routine coordination automatically and only interrupt me when a meaningful decision requires my approval."*

### Architectural Principles

1. **Deterministic for Mechanics, LLM for Reasoning**: Standard calculations (sensor thresholds, vibration limits, inventory balances, budget deduction) are computed deterministically in code. Amazon Bedrock LLM reasoning is used strictly for root-cause synthesis, multi-variable trade-off analysis, and concise human communication.
2. **Epistemic Honesty & Data Provenance**: Every claim generated by an agent must be tagged with its epistemic category:
   - `[OBSERVED]`: Direct telemetric or physical sensor measurement (e.g. 6.82 mm/s vibration).
   - `[MODELED]`: Inferred through physics, flow dynamics, or memory patterns (e.g. silt ingestion in sandstone strata).
   - `[ESTIMATED]`: Forward-looking calculations (e.g. $1,420 repair cost, 3.5h downtime).
   - `[VERIFIED]`: Confirmed post-actuation physical state (e.g. vibration normalized to 1.4 mm/s).
3. **No Phantom Delegations**: Agents never invent phantom contractors, hallucinate credentials, or dispatch unverified third parties.
4. **Attention as the Rarest Resource**: Human operators are never bombarded with routine status pings. If a task falls within pre-authorized boundaries, it is executed silently in the background.

## 2. Multi-Agent Hierarchy & Roles

Atlas Steward deploys 4 specialized agents utilizing the **Strands Agents SDK**:

```
                                  ┌────────────────────────┐
                                  │      STEWARD AGENT     │
                                  │ (Primary Orchestrator) │
                                  └───────────┬────────────┘
                                              │
                      ┌───────────────────────┼───────────────────────┐
                      ▼                       ▼                       ▼
           ┌─────────────────────┐ ┌─────────────────────┐ ┌─────────────────────┐
           │   OPERATIONS AGENT  │ │   RESOURCE AGENT    │ │     RISK AGENT      │
           │  Telemetry, Shifts, │ │ Inventory, Vendors, │ │  Safety Invariants, │
           │  Work Order Dispatch│ │ Quotes, Reorders    │ │  Blast Radius & Pol │
           └─────────────────────┘ └─────────────────────┘ └─────────────────────┘
```

### 2.1. Steward Agent (Coordinator & Priority Floor Guardian)
- **Role**: Primary orchestrator and human interface guardian.
- **Allowed Tools**: `get_water_status`, `send_notification`, `update_task`, `record_outcome`.
- **Key Responsibilities**:
  - Translates the operator's durable objective into discrete operational queues.
  - Monitors community **Priority Floor** baselines (Water, Sanitation, Energy, Food, Shelter, Connectivity).
  - Evaluates whether operational anomalies can be handled autonomously or require human intervention.
  - Formulates structured decision cards for the human cockpit when boundaries are breached.

### 2.2. Operations Agent (Field & Asset Specialist)
- **Role**: Infrastructure telemetry monitor and maintenance coordinator.
- **Allowed Tools**: `get_asset_status`, `get_operator_availability`, `get_maintenance_history`, `schedule_inspection`, `create_work_order`, `verify_completion`.
- **Key Responsibilities**:
  - Ingests high-frequency Modbus IoT telemetry (vibration, flow rate, pressure, temperature).
  - Executes routine inspection schedules, chlorine dosing, and filter backwashing.
  - Dispatches certified technicians and performs post-repair physical telemetry verification.

### 2.3. Resource Agent (Supply Chain & Vendor Matchmaker)
- **Role**: Inventory manager and contractor negotiator.
- **Allowed Tools**: `get_inventory`, `find_service_provider`, `request_quote`.
- **Key Responsibilities**:
  - Monitors consumables inventory against dynamic safety buffers.
  - Maintains verified contractor registries with licensing, SLA ratings, and specialties.
  - Requests structured quotes with itemized parts/labor breakdowns and warranties.

### 2.4. Risk Agent (Safety Invariants & Policy Evaluator)
- **Role**: Safety evaluator and blast radius quantifier.
- **Allowed Tools**: `get_water_status`, `get_asset_status`.
- **Key Responsibilities**:
  - Quantifies downstream impact (downtime hours, population affected, revenue loss).
  - Evaluates policy compliance against statutory water safety laws and local bylaws.
  - Enforces fail-safe postures (e.g. emergency cutoff triggers on major line bursts).

## 3. Integration of the 4 Autonomy Levels

Atlas Steward enforces four discrete levels of autonomy:

```
┌─────────────┬────────────────────────────────────────────────────────┬──────────────────────────────────────────┐
│ Level       │ Definition & Scope                                     │ Example Permitted Actions                │
├─────────────┼────────────────────────────────────────────────────────┼──────────────────────────────────────────┤
│ OBSERVE     │ Read-only telemetry sampling, sensor polling, audits.  │ `get_water_status`, `get_asset_status`   │
│ RECOMMEND   │ Multi-option trade-off synthesis & blast radius modeling│ Risk scoring, alternative contractor map│
│ PREPARE     │ Draft work orders, stage replacement parts, get quotes │ `request_quote`, staging inventory SKU   │
│ EXECUTE     │ Active physical intervention or technician dispatch.   │ `create_work_order` (<= $500), backwash  │
└─────────────┴────────────────────────────────────────────────────────┴──────────────────────────────────────────┘
```

The transition from background autonomous coordination to human escalation follows an immutable, deterministic state machine:

```

         [OBSERVE TELEMETRY]
   (Vibration, Flow, Pressure, Temp)
                  │
                  ▼
         [ANOMALY DETECTED?] ────────── NO ──► [SILENT ROUTINE EXECUTION]
                  │                            - 18 background tasks continue
                  YES                          - State logged silently
                  │
                  ▼

   - Operations Agent queries maintenance history
   - Resource Agent queries Strands Memory Bank (MEM-2025)

                  ▼

         │                 │

         │                 │

[AUTONOMOUS EXECUTE]  [HALT & ESCALATE EXCEPTION]
```

## 5. Decision Card Structure for Escalated Exceptions

When an exception is escalated to the operator cockpit, the Steward Agent formats the decision with strict contextual rigor:

1. **What Happened**: Objective summary of the anomalous sensor trigger.
2. **Why It Matters**: Concrete impact on community water supply and infrastructure asset health.
3. **Evidence Layer (`EvidenceDisplay`)**: Grounded claims classified into `[OBSERVED]`, `[MODELED]`, `[ESTIMATED]`, and `[VERIFIED]`, complete with data source, timestamp, confidence score, and assumptions.
4. **Policy Boundary Triggered**: Explicit rule reference (e.g. `POL-03-SPEND-THRESHOLD: Estimated repair cost $1,420 exceeds auto-approval boundary $500`).
5. **Evaluated Options Matrix**: Comparative breakdown of 3 concrete actions with cost, downtime, and risk scores.
6. **Recommended Action**: Clear agent recommendation with supplier, warranty, and estimated recovery time.
7. **Consequences If Ignored**: Bulleted list of failure scenarios if the human dismisses or delays the decision.

---

## 6. Human Action Lifecycle & Closed-Loop Memory

When the operator acts on the escalated decision card:

- **APPROVE**: Dispatches work order `create_work_order`, schedules technician, triggers `verify_completion` upon completion, and anchors verified lesson into Strands Memory (`record_outcome`).
- **REJECT**: Cancels proposal, maintains safe standby posture, and updates memory bank with operator preference.
- **MODIFY**: Allows operator to adjust spend ceiling, choose alternative supplier, or add custom technical notes.
- **PAUSE**: Freezes autonomous execution loop immediately for physical inspection.
